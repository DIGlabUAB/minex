# minex 0.3.0 design spec — Hierarchical Delta Debugging (sub-expression reduction)

Date: 2026-07-21
Status: DRAFT — to be adversarially reviewed before planning
Milestone: 0.3.0 (second of three: 0.2.0 core [done], 0.3.0 HDD, 0.4.0 LLM)
Depends on: 0.2.0 (the reduce/verify engine, matcher, run_code, minex_result)
Research: docs/research/2026-07-20-ast-tooling.md (tested, no new dependency)

## Goal

Let `minex` reduce *within* a single top-level statement, not just across
statements. Today the reduction unit is the top-level statement, so a failure
buried inside one large expression (a `|>`/`%>%` pipeline, a nested call, a
`{ }` block) cannot be shrunk. 0.3.0 adds Hierarchical Delta Debugging (HDD)
over the R parse tree so the failing sub-expression is isolated too.

## The gap (verified against the 0.2.0 build)

```r
script <- c(
  "x <- 1:10",
  "y <- 20",
  "result <- x |> rev() |> sqrt() |> sum() |> log('oops not a base')"
)
minex(code = script)   # 0.2.0
# reduces 3 -> 2: drops `y <- 20`, KEEPS the whole pipeline unchanged,
# because the pipeline is ONE top-level statement.
```

Desired 0.3.0 result:

```r
result <- x |> log('oops not a base')
```

The culprit stage is isolated; the irrelevant `rev()`/`sqrt()`/`sum()` stages
are removed.

## Guiding constraints

- **No new dependency.** Base R `utils::getParseData()` + `utils::getParseText()`
  provide the parse tree with character offsets; deletion is span-based on the
  ORIGINAL source text, which preserves the user's formatting (research-tested).
  `treesitter`/`xmlparsedata` were evaluated and rejected (dependency weight).
- **Every candidate must be syntactically valid.** HDD only ever deletes whole
  parse-tree nodes, and always deletes a node together with its adjacent
  connective (see below), so no candidate is a syntax error by construction.
- **Reuse the 0.2.0 engine.** HDD does not replace `ddmin`; at each tree level it
  applies the existing reduce/verify machinery to that level's sibling set. The
  oracle (`run_code` + matcher) is unchanged — HDD only changes which candidate
  *source strings* get tested.
- **Preserve honesty and back-compat.** Statement-level behavior is unchanged
  unless the user opts into expression-level reduction; the `minex_result`
  contract is preserved.

## The critical rule (research finding — the one that fails SILENTLY)

Deletion must remove a node **plus its adjacent connective**, atomically:

- **Pipeline stage**: delete the stage AND the preceding `|>` / `%>%`. Deleting
  only the stage's call leaves a dangling operator -> hard parse error (loud,
  caught by reparse check).
- **Call argument**: delete the argument AND its adjacent comma. Deleting only
  the argument yields `f(a, , c)`, which **parses** (R allows missing args) but
  is semantically different and visually broken — a SILENT failure. This case
  needs its own explicit test; a "does it parse" check will not catch it.

## Architecture

```
R/
  hdd.R          NEW   HDD orchestration: level-by-level tree reduction
  parse-tree.R   NEW   getParseData wrapper; node model; span/connective deletion; reparse-validity
  minex.R        MOD   new `granularity` argument; wire HDD after statement-level reduction
  ... (0.2.0 files unchanged)
```

### Data flow

```
statements (from split_statements)
  -> statement-level reduce (0.2.0, unchanged): drop irrelevant whole statements
  -> for each SURVIVING statement, if granularity includes "expression":
        parse-tree it (getParseData)
        HDD: for each tree level (BFS by depth):
           enumerate reducible sibling nodes at this level
           build candidate = original source with (node + connective) span removed
           reparse-check the candidate (must parse); skip if invalid
           feed candidate strings to the 0.2.0 reduce/verify phases via the oracle
        reconstruct minimized source from surviving spans
  -> minex_result (with the reduced, still-readable code)
```

### Node model (parse-tree.R)

From `getParseData(parse(text, keep.source = TRUE))`: each token/expr has
`line1/col1/line2/col2`, `parent`, `terminal`, `token`, `text`. We build an
expr-node tree; each node knows its character span in the original text and its
adjacent connective (operator before a pipe stage; comma beside a call arg).

Reducible node categories (initial scope):
- pipeline stages (`|>`, `%>%`) — delete stage + preceding operator
- call arguments — delete arg + adjacent comma (handle first/last/middle)
- top-level statements inside a `{ }` block — delete the statement line
- `if`/`for`/`while` bodies where removal keeps validity

NON-reducible (kept whole, initial scope): a call's function head, operator
operands that would unbalance the expression, anything whose removal cannot be
made valid by the connective rule. When unsure, DO NOT delete (conservative:
the worst case is we fail to reduce, never that we corrupt).

## Guarantee

Statement-level reduction gives one-minimality over statements (0.2.0). HDD
gives **1-tree-minimality**: no single reducible tree node can be removed while
still reproducing the failure. This is strictly stronger than flat
one-minimality. The verify (fixpoint) sweep from 0.2.0 runs at each level to
preserve it, because CDD-style reduction alone may miss it.

## API surface (OPEN — flag for review)

Provisional: a `granularity` argument on `minex()`:

```r
minex(file = "x.R", granularity = c("statement", "expression"))
```

- `"statement"` (default) — 0.2.0 behavior exactly, no AST work. Back-compat.
- `"expression"` — after statement-level reduction, descend into each surviving
  statement with HDD.

Open questions (for the review + user):
1. Default: keep `"statement"` (safe, back-compat) or make `"expression"` the
   default once proven? Provisional: keep `"statement"` default in 0.3.0.
2. Escalation: always do expression-level when asked, or only when the
   statement-level result is still "large"? Provisional: always when asked.
3. Result reporting: `n_minimal` is currently a statement count. With
   sub-expression reduction the unit is fuzzier. Provisional: report both a
   statement count and a character-length reduction; keep `as.character()`
   returning the reduced source.

## Cost

HDD multiplies oracle calls: each surviving statement's tree adds levels, each
level runs reduce/verify. `max_oracle_calls` (0.2.0) still bounds total work and
`complete = FALSE` still labels a truncated search honestly. The `callr`
per-call cost (~300ms) makes the budget especially relevant here; the `bench/`
corpus (0.2.0) gains pipeline/nested-call scripts to measure HDD cost.

## Testing strategy (TDD order)

1. `test-parse-tree.R` — node model + span extraction; **the comma hazard**
   (delete middle/first/last arg -> valid, no `f(a, , c)`); pipeline-stage
   deletion for both `|>` and `%>%`; reparse-validity rejects a bad span.
2. `test-hdd.R` — level-by-level reduction on a synthetic tree reaches
   1-tree-minimality; conservative non-deletion of non-reducible nodes.
3. `test-minex.R` (extend) — `granularity = "expression"` isolates a pipeline
   stage end-to-end; `"statement"` default unchanged; budget still bounds it.
4. Comment handling: a trailing `# comment` on a deleted line (research flagged
   this as untested) — decide and test.

## Explicitly out of scope for 0.3.0

- Perses-style syntax-guided reduction (needs a grammar; a possible 0.4.0+).
- Reformatting/normalizing surviving code (we preserve original formatting).
- Reducing inside strings or comments.

## Open risks to probe in review

- **Silent comma corruption** if the connective rule is wrong for an edge case
  (first arg, last arg, single arg, trailing comma, `...`).
- **Non-associative operators**: deleting an operand of `a - b - c` changes
  meaning; ensure only safely-removable nodes are in scope.
- **srcref/getParseData accuracy** with nested pipes, multi-line calls, comments,
  and the native vs magrittr pipe.
- **Blow-up**: HDD on a large statement could explode oracle calls; confirm the
  budget genuinely bounds it and the trace marks truncation.
- **Interaction with truncation** (0.2.0): truncation drops post-failure
  statements first; HDD then works within survivors — confirm no conflict.
