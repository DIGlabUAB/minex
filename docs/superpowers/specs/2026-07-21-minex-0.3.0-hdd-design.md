# minex 0.3.0 design spec — Hierarchical Delta Debugging (sub-expression reduction)

Date: 2026-07-21
Status: reshaped after adversarial review (round 1, 4 critics, R-verified); ready for round-2 review
Milestone: 0.3.0 (second of three: 0.2.0 core [done], 0.3.0 HDD, 0.4.0 LLM)
Depends on: 0.2.0 (reduce/verify engine, matcher, run_code, minex_result)
Research: docs/research/2026-07-20-ast-tooling.md

## Adversarial review outcomes (round 1)

Four critics attacked the first draft; every empirically-checkable finding was
reproduced in R before acceptance. Two decisions (user-approved) reshaped it:

1. **Scope narrowed to the two research-tested cases**: native `|>` / magrittr
   `%>%` **pipeline stages** and **positional call arguments**. Everything else
   is explicitly deferred (see Deferred).
2. **HDD\*, not single-pass HDD**: re-parse from text between passes and loop
   until a full pass deletes nothing. Single-pass HDD is *provably not*
   1-tree-minimal (the 0.2.0 sweep is intra-level; the guarantee needs an
   inter-level fixpoint — the HDD vs HDD\* distinction, Misherghi & Su 2006).
   Re-parsing between passes also fixes stale spans after deletion.

Also fixed from the draft (all R-verified): `SPECIAL` token ≠ pipe (`%in%`,
`%o%` are SPECIAL too); pipe chains are **left-nested**, not flat siblings;
commas are siblings of args, not children; the leftmost pipe operand and all
infix-operator operands silently corrupt on deletion; "formatting preserved" was
overstated (whitespace is not a token); the oracle-call budget was hand-waved.

## Goal

Let `minex` reduce *within* a top-level statement, for two node kinds:
**pipeline stages** and **positional call arguments**. A failure buried in one
large expression can then be shrunk too, not just deleted whole-statement.

## The gap (verified against the 0.2.0 build)

```r
minex(code = c("x <- 1:10", "y <- 20",
               "result <- x |> rev() |> sqrt() |> sum() |> log('oops')"))
# 0.2.0: drops `y <- 20`, KEEPS the whole pipeline (it is ONE statement).
# 0.3.0 target: result <- x |> log('oops')
```

## Scope (0.3.0)

Reducible node kinds — exactly two:

1. **Pipeline stage** — a right-hand stage of a `|>` or `%>%` chain. Delete the
   stage **and its preceding pipe operator** as one span.
2. **Positional call argument** — an unnamed argument in a call's argument list.
   Delete the argument **and one adjacent comma** (position rule below).

### Deferred (explicitly out of 0.3.0 → 0.3.1+)

Each carries a silent-corruption or untested risk the review established:

- **Named arguments** (`f(x, y = 2, z)`) — getParseData gives NO node wrapping
  `y = 2`; deleting the value node yields `f(x, y = z)` which parses but makes
  `z` the value of `y` (R-verified silent corruption). Needs a synthesized
  `SYMBOL_SUB..value` region — deferred.
- **Infix-operator operands** (`a - b - c`, `a / b`, `a && b`) — deleting an
  operand parses but silently changes the value/meaning (`10-3-2`=5 vs
  `10-2`=8, R-verified). No syntactic "safe operand" predicate exists.
- **Block statements** (`{ ... }`) and **control-flow bodies** (`if`/`for`/
  `while`) — never research-tested; different validity rules (an `if`-body
  deletion can change branch semantics).

## Guiding constraints

- **No new dependency.** Base `utils::getParseData(parse(text, keep.source =
  TRUE))` + span deletion on the ORIGINAL text. `keep.source = TRUE` is passed
  every time (default is FALSE non-interactively, and FALSE → getParseData
  returns NULL); guard with `stopifnot(!is.null(pd))`.
- **Every candidate must parse.** Deletion removes a whole node span plus its
  connective; a reparse check rejects any candidate that does not parse. Reparse
  is a cheap LOCAL check — it does NOT spawn a `callr` process and does NOT
  consume the oracle-call budget.
- **Reuse the 0.2.0 engine.** HDD\* generates candidate source strings; the
  oracle (`run_code` + matcher) and reduce/verify machinery are unchanged.
- **Back-compat.** `granularity = "statement"` (default) is byte-for-byte the
  0.2.0 path — no getParseData call, no `hdd.R` cost, zero perf delta.

## Node detection (concrete — the draft was hand-wavy here)

From `getParseData`:

- **Native pipe**: `token == "PIPE"`. **Magrittr/other**: `token == "SPECIAL"`
  **AND** `text %in% c("%>%", "%|>%")` — NEVER by `token == "SPECIAL"` alone
  (`%in%`, `%o%`, etc. are SPECIAL; R-verified). This is an explicit pipe
  allowlist.
- **Pipe spine flattening**: a chain `a |> b() |> c() |> d()` is LEFT-NESTED —
  each PIPE sits at a different parent depth, so BFS-by-depth finds one pipe per
  level, never the stages as siblings (R-verified). Build a synthetic flat stage
  list by walking the left spine: `[a (data), b(), c(), d()]`. The **leftmost
  element (the data source `a`) is NON-reducible** — it has no preceding pipe,
  and deleting it + the following pipe parses (`b() |> c()`), a silent wrong
  reduction. Only stages 2..n are reducible.
- **Positional call args**: the call's argument exprs are children of the call
  expr; the `','` tokens are their siblings (no parent edge). Enumerate arg
  positions by scanning the child list. An arg is *positional* iff it is not
  preceded by a `SYMBOL_SUB`/`EQ_SUB` (named-arg markers) — named args are
  skipped (deferred). Comma selection by position:
  - first positional arg → delete node + the comma **after** it
  - middle/last → delete node + the comma **before** it
  - single arg → delete node only (→ `f()`)
  (all four R-verified to parse)

## Algorithm: HDD\*

```
hdd_star(statement_source, oracle, budget):
  repeat:
    pd      <- getParseData(parse(text = current, keep.source = TRUE))
    stopifnot(!is.null(pd))
    nodes   <- reducible_nodes(pd)          # flattened pipe stages 2..n + positional args
    if nodes is empty: break
    # one HDD level = the reducible sibling set at one tree depth;
    # apply the 0.2.0 reduce (cdd) + verify (fixpoint) over that set's
    # candidate source strings, via the shared oracle/budget.
    changed <- reduce_level(nodes, oracle, budget)   # deletes confirmed-removable nodes
    current <- reconstruct(current, surviving spans) # + whitespace trim
    if not changed: break                            # inter-level fixpoint => 1-tree-minimal
  return current
```

Re-parsing at the top of each pass (not once up front) is what makes spans
valid after deletion AND makes this HDD\* (1-tree-minimal), per the review.

## Guarantee

**1-tree-minimality** over the two reducible node kinds: after HDD\* converges,
no single reducible pipeline stage or positional argument can be removed while
the candidate still **reproduces the same diagnostic**. "Same diagnostic," not
merely "some failure": because sub-expression deletion changes meaning, the
matcher must confirm the candidate reproduces the recorded condition
(message/class per `match`), so a candidate that fails via a *different*
mechanism is rejected — preserving the 0.2.0 soundness posture. The excluded
node kinds (leftmost operand, infix operands, named args) are what keep the
failure mechanism stable.

## Budget (the draft hand-waved this — now a mechanism)

- **One shared running counter and cache** thread through ALL HDD\* sub-calls
  for a given `minex()` run (across every statement × pass × level), not a fresh
  `max_oracle_calls` per `ddmin()` invocation.
- Reparse-rejected candidates are **free** (local, no `callr`, no budget charge).
- On exhaustion, **stop the entire HDD\* process** (not just the current
  statement), set `complete = FALSE`, and surface it honestly (warning + print
  note + trace marker), exactly as 0.2.0 does for statement-level.
- The final `minex_result$oracle_calls` is the SUM across all sub-calls.

## API surface

```r
minex(file = "x.R", granularity = c("statement", "expression"))
```

`match.arg`-style **single-select** (matching `condition`/`match`/`algorithm`/
`backend`). `"statement"` (default) = exact 0.2.0 behavior. `"expression"` =
after statement-level reduction, run HDD\* on each surviving statement. There is
no multi-value set; "expression" already implies statement-level ran first.

HDD is **internal to `minex()`** — not exported like `ddmin()`/`reduce_rows()`
(it is parse-tree-specific, not a generic engine). Files: `R/parse-tree.R`
(node model, detection, span/connective deletion, reconstruction) and
`R/hdd.R` (the HDD\* loop).

## `minex_result` back-compat (mandated, not "provisional")

- `n_minimal` stays an **integer count of surviving top-level statements** =
  `length(code)`. NEVER overloaded (the print method's `%d` and existing tests
  depend on it).
- `code` stays a **character vector, one element per surviving statement**;
  `code[i]` is the HDD\*-reduced source of surviving statement `i`. Same shape
  as 0.2.0, so `as.character()` (`paste(code, collapse="\n")`) is unaffected.
- New fields for the HDD signal: `n_chars_original`, `n_chars_minimal`.
- `print.minex_result`: an **additive** line (gated on `granularity ==
  "expression"`) reporting the character reduction, so HDD progress is visible;
  the existing header/`%d`/"may still be reducible" lines are untouched (tests
  grep them).
- `trace` gains `stmt_index` and `level` columns and a monotonic `call` offset,
  so HDD sub-call rows don't collide; `phase` still `reduce`/`verify`.

## Formatting (claim downgraded per review)

Result is **syntactically valid with formatting approximately preserved** — NOT
"indistinguishable from hand-edited." Whitespace is not a getParseData token, so
node+connective deletion leaves residue (double spaces, a collapsed
one-stage-per-line layout). Reconstruction includes a **whitespace-trim step**:
collapse the run of spaces left between the two surviving neighbors of a deleted
span. Trailing comments: a span whose line carries a trailing `# comment`
(getParseData exposes COMMENT tokens via NEGATIVE parent ids, disjoint spans) is
treated as **non-reducible** (conservative), matching `split_statements`'
precedent of dropping standalone comments rather than reattaching.

## Testing strategy (TDD order)

1. `test-parse-tree.R` — detection + deletion units:
   - pipe-stage span (native `|>` AND `%>%`); leftmost operand is non-reducible;
     `%in%`/`%o%` are NOT detected as pipes.
   - positional-arg comma rule: first, middle, last, single (`f()`); named args
     are skipped (not deleted); `f(a, , c)` is never produced.
   - reparse rejects a dangling-operator span; whitespace-trim yields clean text.
   - `keep.source=TRUE` guard; NULL parse-data handled.
2. `test-hdd.R` — HDD\* fixpoint: a case where a stage becomes removable only on
   a SECOND pass (discriminates HDD\* from single-pass); conservative
   non-deletion of deferred kinds; 1-tree-minimality of the result.
3. `test-minex.R` (extend) — `granularity="expression"` isolates a pipeline
   stage and a positional arg end-to-end; `"statement"` default byte-unchanged;
   shared budget bounds total calls and sets `complete=FALSE` honestly;
   `n_minimal`/`code` shapes unchanged.
4. `bench/` — add pipeline and nested-call scripts to measure HDD\* cost.
