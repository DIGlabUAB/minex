# minex 0.2.0 design spec

Date: 2026-07-20
Status: approved and adversarially reviewed; ready for implementation planning
Milestone: 0.2.0 (core improvements) -- first of three (0.2.0 core, 0.3.0 HDD
sub-expression reduction, 0.4.0 local LLM integration)

## Adversarial review outcomes (2026-07-20)

Five parallel critics attacked this spec (algorithmic soundness, R semantics,
CRAN compliance, API/back-compat, internal consistency); every empirically
checkable finding was reproduced in R before acceptance. Four findings changed
the design; the rest became mechanical fixes folded into the sections below.

Design changes (all confirmed in R):

1. **`ddmin()` return stays a plain vector** (subclass-wrapper approach).
   Attaching attributes to the return broke `identical(result, "fox")` in
   `test-ddmin.R:4` (verified). Metadata (`complete`, `oracle_calls`, `trace`)
   is carried only by the `minex_result` / `reduce_rows` wrappers. `ddmin()`
   exposes its call count and completeness through a documented side channel
   that its existing `identical()`-based tests ignore.
2. **The prefilter phase is CUT.** Greedy single-element removal is unsound on
   non-monotonic oracles -- it can strand the reducer in the larger of two
   one-minimal basins and produce a *bigger* result. Verified counterexample:
   oracle reproduces iff `X %in% S || all(c("Y","Z") %in% S)`; `ddmin` alone
   returns `{X}` (size 1), prefilter+`ddmin` returns `{Y,Z}` (size 2). The
   engine is now two phases: `reduce -> verify`. `verify` alone already
   guarantees one-minimality.
3. **`options(warn = 2)` is honored.** `invokeRestart("muffleWarning")` fires
   before R's warning->error promotion, silently reclassifying the target
   (verified: old runner reports an error, new runner a muffled warning). The
   warning handler now checks `getOption("warn")` and records an error when
   `>= 2`.
4. **Parity test asserts "both one-minimal AND equal size",** not identical
   membership. One-minimal sets are not unique, so exact set-equality would
   false-fail on legitimately interchangeable statements while still missing
   nothing real (a bloated or non-minimal result fails the size / minimality
   check).

Mechanical fixes folded in below: `1:NA` truncation guard; `print`/`target`
reconciliation; `match.arg` relocation; a single `verbose` predicate;
`failing_index` moved out of `run_code` into `pick_target_index`;
condition-type-not-found guard; `^bench$` added to `.Rbuildignore`; clipboard
examples use `\dontrun`; WORDLIST + DOI gate; `packageStartupMessage` filtered
from message capture; trace bail-out marker; TDD order corrected; multi-source
input warning.

Confirmed correct (survived attack): one-minimality via fixpoint sweep;
cache/budget accounting; `callr` serialization; handler nesting order;
`reduce_rows` attribute non-leak; the "resubmission" framing (0.1.0 **is** on
CRAN, published 2026-07-16).

## Goal

Improve `minex` without breaking the 0.1.0 API or adding a runtime dependency,
and prepare a CRAN resubmission. Every change is additive: an existing
`minex(code = script)` call keeps working, only faster and smaller (it gains
free failure-point truncation and the verify phase automatically).

## Guiding constraints

- **One runtime dependency.** `Imports: callr` stays unchanged. `clipr` enters
  `Suggests` only. No `cli`, no `CodeDepends`, no Bioconductor.
- **Preserve the one-minimality guarantee.** `ddmin()` documents a one-minimal
  result (`R/ddmin.R:5-7`); nothing may weaken that silently.
- **Honest labelling over silent guarantees.** When a result is valid but not
  proven minimal, the object and the printout must say so.
- **Reduce oracle *call count*, not wall-clock constant factors.** Persistent
  sessions and parallelism are explicitly out of scope (a later performance
  milestone).
- **TDD.** Tests precede implementation, load-bearing files first.
- **Meaningful names.** No conversational shorthand (no "phase A/B/C") in
  identifiers, data, or messages.

## Scope: what ships in 0.2.0

1. Failure-point truncation (free; shrinks input before delta debugging)
2. `condition = "error" | "warning" | "message" | "any"`
3. `max_oracle_calls` safety limit + honest `complete` flag
4. CDD algorithm, selectable via `algorithm =`, with a fixpoint sweep that
   preserves one-minimality
5. Function-valued `match`
6. Clipboard input; verbose + structured trace; `bench/` corpus

### Explicitly rejected (with evidence)

- **Static dependency pre-filtering** -- measured 12.5% reduction on a script
  built to favour it. See `docs/research/2026-07-20-static-prefiltering.md`.
- **Monotonicity fast-path** (`assume_monotonic`) -- unsound for R scripts
  (ordering, side effects, non-determinism, laziness). See
  `docs/research/2026-07-20-delta-debugging-algorithms.md`.
- **`CodeDepends`** -- Bioconductor dependency + empirically unsound tree-shaking.
- **`cli` dependency** -- verbose uses base `message()` instead.

### Deferred to 0.3.0

- **HDD sub-expression reduction.** Foundation already researched and tested:
  base R `utils::getParseData()` + `getParseText()` suffice for
  source-preserving subtree deletion, no dependency. Critical rule found:
  delete a node **plus its adjacent connective** (operator or comma) as one
  atomic span; the comma case (`f(a, b, c)` -> `f(a, , c)`) fails *silently*.
  See `docs/research/2026-07-20-ast-tooling.md`.

  cdd.R            NEW       "reduce" phase: CDD round sizing (closed-form)
  sweep.R          NEW       "verify" phase: single-element removal to fixpoint
  match.R          NEW       matcher construction; shorthands -> functions
  oracle.R         MODIFIED  run_code(): condition collection, observed state, failing index
  truncate.R       NEW       failure-point location
  parse.R          unchanged split_statements()
  minex.R          MODIFIED  front end wiring
  reduce-rows.R    MODIFIED  gains algorithm + max_oracle_calls passthrough
  trace.R          NEW       verbose messages + structured trace object
  clipboard.R      NEW       clipr-guarded read
  print.R          MODIFIED  reports complete/incomplete, call counts
  minex-package.R  unchanged
bench/             NEW       corpus + harness (git-tracked, .Rbuildignore'd)

### Data flow

```
code / file / clipboard
   -> split_statements()
   -> build_matcher(match)  ------------.  (shared equality predicate, both phases)
   -> run_code(full) -> target (conditions list, observed)
   -> pick_target_index(conditions, matcher, condition)  -> failing_index (or NA)
   -> if !is.na(failing_index): truncate statements[1:failing_index]  (free)
   -> ddmin(statements, oracle, algorithm, max_oracle_calls, verbose)
        -> reduce     (cdd | classic block-halving)
        -> verify     (remove_removable_singles to fixpoint -> one-minimality)
   -> minex_result { code, complete, oracle_calls, trace, ... }
```

### Naming decisions

| Identifier | Value / form |
|---|---|
| trace `phase` column | `"reduce"` / `"verify"` (never A/B/C; prefilter cut) |
| condition->string helper | `condition_summary()` (not `summarize` -- collides with dplyr) |
| CDD growth constant | `PROBDD_GROWTH_RATE <- 1 / (1 - exp(-1))` (expression, not `1.582`) |
| CDD round vars | `round_index`, `p_round`, `p_initial`, `block_size` (not `r`, `p_r`, ...) |
| budget condition class | `minex_oracle_limit_reached` (traces back to `max_oracle_calls`) |
| single-element sweep fn | `remove_removable_singles()` |
| verbose predicate | `wants_trace(verbose)` / truthiness via `!isFALSE(verbose)` (never bare `if (verbose)`) |

## Component specs

### 1. Reduction engine (`ddmin.R` + `cdd.R` + `sweep.R`)

Signature:

```r
ddmin(items, interesting,
      algorithm        = c("cdd", "ddmin"),
      max_oracle_calls = Inf,
      verbose          = FALSE)
```

**Return shape (back-compat).** `ddmin()` returns `items[kept]` as a **plain
vector**, exactly as 0.1.0 -- no attributes on the value, so existing
`identical()`-based tests (`test-ddmin.R:4`, `:19-23`) pass unchanged. It exposes
`oracle_calls` and `complete` through a side channel its tests ignore: either a
dedicated environment argument the caller reads, or attributes that the front
ends strip before returning. `minex()` / `reduce_rows()` are the only functions
that surface the metadata, via the `minex_result` object. Rationale: `ddmin()`
is documented as "returns the one-minimal subset"; keep that literally true and
leave the trusted 0.1.0 contract undisturbed.

Two phases (prefilter cut -- see review outcome 2):

- **reduce** -- CDD (default) or classic block-halving. Both share the index-set
  cache unchanged.
- **verify** -- `remove_removable_singles()` to fixpoint: restores
  one-minimality (CDD misses it ~1.1% of runs). Only does extra passes when
  something is actually removable. "To fixpoint" is load-bearing -- a single
  pass is insufficient, since removing element i can make j removable.

CDD reduce phase (round 0 skipped -- see below):

```
p_initial  = 1 / len
p_round    = min(p_initial * PROBDD_GROWTH_RATE^round_index, 1)
block_size = argmax over s in 1..len of  s * (1 - p_round)^s
n_blocks   = ceiling(len / block_size)      # NOT round(): see note
if n_blocks <= 1: round_index <- round_index + 1; next   # skip empty-complement
partition kept into n_blocks blocks; test each complement (keep = len - block):
  hit    -> kept <- kept minus block; round_index <- 0
  no hit -> round_index <- round_index + 1  (stop if n_blocks >= len)
```

**CDD fidelity note (review finding M3).** The naive `n_blocks = max(1,
round(len/block_size))` yields `n_blocks == 1` for every `len >= 3` at
`round_index == 0` -- a single block whose complement is empty, testing nothing
(verified in R for len = 3, 5, 10, 20). Two corrections: (a) skip any round
where `n_blocks <= 1`; (b) use `ceiling`, and partition by *target removal size*
so each candidate removes ~`block_size` elements as the paper specifies, rather
than approximating via `round(len/block_size)`. The `bench/` corpus must confirm
the "~52% fewer calls" claim holds under this reformulation before `"cdd"`
becomes the default.

Reference: Zhang, Xu, Tian, Cheng & Sun, "Toward a Better Understanding of
Probabilistic Delta Debugging," ICSE 2025, DOI 10.1109/ICSE55347.2025.00117.

**Budget.** Counter lives in `test()`, charged **only on cache misses**. On
exhaustion, signal `minex_oracle_limit_reached`, caught around both phases,
setting `complete <- FALSE`. Safe because `kept` is only ever assigned from a
confirmed-TRUE test.

*Precondition exemption (review finding M2).* The mandatory full-set precondition
test (`ddmin.R:68`) is **exempt from the budget** -- it must always run, so
`kept` is never returned unverified. If `max_oracle_calls < 1`, `stop()` with a
clear message rather than returning the unconfirmed full set. A budget signal
raised inside a `test()` is raised *before* the result is written to cache or
`kept`, so a bail leaves no half-written state, and it must be distinguishable
from the separate "interesting is FALSE for the full set" error.

**Open decision (resolve via `bench/`):** default `algorithm`. Provisionally
`"cdd"`; confirm it beats `"ddmin"` on R scripts (call count AND output size)
before committing. If CDD is not strictly better on both, default stays
`"ddmin"`.

### 2. Condition capture & matching (`oracle.R` + `match.R` + `truncate.R`)

New `run_code()` contract (note: `run_code` does NOT compute `failing_index` --
see below):

```r
list(
  observed   = TRUE,        # FALSE on timeout/crash -- "could not watch it run"
  conditions = list( list(type=, message=, classes=, stmt_index=), ... )
)
```

`observed = FALSE` (timeout/crash) is distinct from `conditions = list()` (ran
cleanly) -- the 0.1.0 code conflated them (`R/oracle.R:36-42`). An unobserved
call also sets the result's `complete = FALSE`.

Capture switches from single `tryCatch` to a statement loop under
`withCallingHandlers` (nesting verified: `withCallingHandlers(tryCatch(loop,
error=), warning=, message=)` collects `[warning@3, warning@5, error@7]`
correctly):

- errors: caught, stop the loop; recorded with `stmt_index` = where the loop
  halted.
- warnings/messages: recorded via handler + `invokeRestart("muffleWarning" /
  "muffleMessage")` so execution continues.
- **`options(warn = 2)` (review outcome 3):** the warning handler checks
  `getOption("warn")`; when `>= 2` it records the condition as an **error** (R
  would promote it) and stops, instead of muffling. Without this, `warn=2`
  scripts have their target silently reclassified error->warning (verified).
- **`packageStartupMessage` (review finding M10):** filtered out of message
  capture (matched on class), so `library()` banners never become the
  `condition="message"/"any"` target. Captured message text also carries a
  trailing `"\n"`; matchers must normalize it consistently across
  candidate/target.

Everything crossing the `callr` boundary is plain character data (condition
objects do not serialize reliably -- verified round-trip).

**`failing_index` lives in `pick_target_index()`, not `run_code()` (review
finding M4).** Which condition defines the target depends on `condition`/`match`
-- error means "where the loop halted", warning/message means "**last** matching
occurrence", `any` means "last condition of the highest-severity type present"
(**severity order: error > warning > message**, pinned here and in a test).
`run_code()` cannot know this, so it returns only the raw `conditions` list;
`pick_target_index(conditions, matcher, condition)` applies the selection and
returns the index, or `NA` when no condition of the requested type matches.

Matcher (`build_matcher`): resolves `match` (string or function) to a single
equality predicate `function(candidate, target) -> logical`.
`"message"`/`"class"`/`"both"` become built-in functions; a user function passes
through. This same predicate is used by both `pick_target_index()` and the
oracle so they apply an identical notion of "matches the target" -- note this
shares the *equality test*, not the severity/last-match *selection* logic, which
lives only in `pick_target_index()`.

**Condition-type-not-found guard (review finding M7).** If target recording
produces no condition of the requested `condition` type (e.g. `condition =
"warning"` but the script only errors), `minex()` stops with a clear message --
the generalization of 0.1.0's "ran without error; nothing to minimize"
(`minex.R:100-103`). It must not proceed with `failing_index = NA`.

Truncation: only when `failing_index` is **not NA**, set `statements <-
statements[1:failing_index]` before ddmin (`1:NA` would crash -- review finding
C4). Trusted for deterministic scripts (documented). For flaky scripts, if the
first in-`ddmin` oracle call finds the truncated set does not reproduce, fall
back to the untruncated set (costs one oracle call, charged to the budget). The
fallback detects non-reproduction only, not "reproduces via a different cause";
docs must state that truncation is trustworthy only with a specific `match`
(message/class), not a bare `condition="any"`.

### 3. Result object & printing (`print.R` + `trace.R`)

`minex_result` gains: `complete`, `algorithm`, `condition`, `max_oracle_calls`,
`trace`. `target` grows to carry `failing_index` and the full `conditions` list.

**`target` back-compat (review finding C2).** The new `target` MUST retain
top-level `message` and `classes` fields (derived from the selected condition),
because `print.minex_result` (`print.R:7`) and `make_target_oracle` read
`target$message`/`target$classes`. Without them, `is.na(target$message)` becomes
`is.na(NULL)` -> `logical(0)`, and `&&` on a zero-length operand **errors on
every 0.2.0 result** (verified). `print.R` and the `target` constructor change
in lockstep.

Print: complete runs read as today. Incomplete runs append `, incomplete` to the
header and a note naming the cause (budget limit vs. timeout/crash) with the
remedy, plus a `warning()` at return time.

Verbose (`FALSE` / `TRUE` / `"trace"`). Every dispatch uses the named predicates
from the naming table (never bare `if (verbose)`, which errors when `verbose =
"trace"` -- verified `if ("trace")` raises "argument is not interpretable as
logical"):

- `TRUE` -- base `message()` to stderr, on a call-count cadence, labelled by
  phase name (`[reduce]`, `[verify]`), reporting escalation during silent
  stretches.
- `"trace"` -- attach `result$trace`, a data frame:
  `call, phase, size, kept, cached, event`. `cached` separates real ~300ms
  oracle calls from free cache hits. `event` marks non-normal rows (e.g.
  `"budget_exhausted"` on the bail-out row) so a truncated run's trace is
  self-describing rather than requiring a cross-check against `result$complete`
  (review finding on trace bail-out marker). This is what `bench/` consumes.

`format()` / `as.character()` unchanged -- still return bare paste-ready code.

### 4. Front-end wiring (`minex.R` + `reduce-rows.R` + `clipboard.R`)

```r
minex(file=NULL, code=NULL, clipboard=FALSE, oracle=NULL,
      condition=c("error","warning","message","any"),
      match=c("message","class","both"),
      algorithm=c("cdd","ddmin"),
      backend=c("callr","inprocess"),
      timeout=60, max_oracle_calls=Inf, verbose=FALSE)
```

Input precedence: `code` > `clipboard=TRUE` > `file` > error. Clipboard is
**explicit** (not reprex-style implicit) -- a bare `minex()` still errors
helpfully rather than silently reading the clipboard. If more than one source is
supplied (e.g. `file=` and `clipboard=TRUE`), the lower-precedence one is
ignored **with a `warning()`** rather than silently (matches the spec's
honest-labelling principle). An installed-but-empty clipboard falls through to
the existing "no parseable statements" error (`minex.R:93-95`).

`clipboard.R`: `read_clipboard()` guards on `requireNamespace("clipr")` and
`clipr::clipr_available()`, with actionable errors on headless systems.
Output-to-clipboard is **cut** from 0.2.0 (`as.character(result)` +
`clipr::write_clip()` is a user one-liner; YAGNI).

Custom `oracle` still bypasses `condition`/`match`/truncation entirely -- it is
the raw-engine escape hatch, unchanged from 0.1.0. There is no recorded target,
so `pick_target_index`/truncation are skipped by construction. `max_oracle_calls`
still applies (it lives in `ddmin`).

**`backend="inprocess"` soundness caveat (review finding M9).** The inprocess
runner evaluates in `new.env(parent = globalenv())`, which chains to the user's
populated global environment. A candidate that references a name existing in the
caller's workspace resolves it instead of erroring, so over-reduction can produce
false "still reproduces" / "no longer reproduces" verdicts precisely on
`object not found` -- the tripwire the docs rely on. Pre-existing in 0.1.0;
0.2.0 documents it sharply and notes `backend="callr"` (the default) is
unaffected. (Handlers themselves do not leak into the caller -- verified.)

`reduce_rows(data, predicate, algorithm=c("cdd","ddmin"),
max_oracle_calls=Inf, verbose=FALSE)` -- inherits CDD, budget, and `complete`
for free by threading three args into its existing `ddmin()` call. No
truncation/clipboard/condition (not applicable to rows).

## Testing strategy (TDD order)

Order corrected (review findings on TDD inversions): `match.R` precedes
`truncate.R` (truncation's `pick_target_index` consumes the matcher), and
`cdd.R`/`sweep.R` come before extending `test-ddmin.R` (the `algorithm=` dispatch
they feed).

| Order | File | First tests |
|---|---|---|
| 1 | `test-oracle.R` | error/warning/message capture; **`warn=2` -> recorded as error** (regression: old whole-block runner vs new loop runner, not CDD-vs-ddmin); `packageStartupMessage` filtered; user `tryCatch` absorption; timeout -> `observed=FALSE` |
| 2 | `test-match.R` | shorthands resolve; function passthrough; `match.arg` no longer eagerly called; equality predicate shape |
| 3 | `test-truncate.R` | `pick_target_index` severity order + last-match for warnings; `failing_index=NA` -> no truncation, no crash; condition-not-found guard; flaky fallback; last-statement no-op |
| 4 | `test-sweep.R` | single-element removal; fixpoint termination; one-minimality restored from non-minimal input |
| 5 | `test-cdd.R` | `cdd_reduce()` reaches one-minimal directly (independent of engine dispatch); round-0 skipped (no empty-complement test); termination |
| 6 | `test-ddmin.R` (extend) | plain-vector return unchanged (existing assertions pass); `algorithm=` switch; budget sets `complete=FALSE`; precondition exempt from budget; `max_oracle_calls<1` errors; cache still dedupes; **parity** (see below) |
| 7 | `test-minex.R` (extend) | `condition=` incl. not-found guard; clipboard (skip if no clipr); multi-source warning; truncation shrinks input; `verbose="trace"` dispatch; incomplete warning; `warn=2` end-to-end |
| 8 | `test-reduce-rows.R` (extend) | algorithm + budget passthrough; no attribute leak onto the returned data frame |

**Parity test (in 6) -- "both one-minimal AND equal size" (review outcome 4):**
run CDD and ddmin on the same scripts and assert (a) each result is one-minimal
(no single element removable) and (b) `length(cdd) == length(ddmin)`. NOT
identical membership -- one-minimal sets are not unique, so set-equality would
false-fail on interchangeable statements while catching nothing extra (a bloated
or non-minimal CDD result already fails a or b).

## Success criteria

- All existing tests pass **unchanged** (guaranteed by the plain-vector `ddmin`
  return); new tests cover every component above.
- Parity test green under the "both one-minimal AND equal size" definition.
- `bench/` shows CDD strictly better than ddmin on the corpus on **both** call
  count and output size; **if not, the default stays `"ddmin"`** (explicit
  failure branch).
- `R CMD check --as-cran`: 0 errors, 0 warnings; notes only as expected for a
  resubmission.
- A budget-exhausted or timed-out run never claims minimality -- `complete` is
  `FALSE`, the printout says so, a `warning()` fires, and the trace's final row
  carries the `event` marker.
- A script setting `options(warn = 2)` reduces against the promoted error, not a
  muffled warning.
```
